# What to build next

The first release implements a narrow calculation-and-review foundation. It should be improved through actual failures and permissioned customer cases, not by loading the entire research collection into each prompt.

## Next private prototype slice

Use the supplied source-reading recipe and data contract to connect a reviewed PDF/drawing extraction flow to the existing structured inputs. Obtain explicit permission for each real drawing and quote, an approved inference/storage route, and an independent engineering reviewer. Keep manual correction. Record critical-field extraction, source-location accuracy, unknown detection and correction burden. Do not add production upload capability to a static public demonstration.

A private application can start from the original reference arithmetic. Add identity, authorization, retention and versioned case records before real shared use. A separate private repository is a proposal, not an existing asset or authorization to create one. Do not automatically place product code or customer evidence in the public WoW repository.

## Broader methods still deferred

Analogy and parametric estimation; process-specific ML costing; multi-stage yield/rework and recycling; CAD-derived geometry; richer machine/tool selection; lifecycle finance and make/buy; formal function/value analysis; supplier allocations; price-index exposure; and realized-outcome measurement all need their own inspected derivations, data and tests.

For a predictor, distinguish quotes, actual resource use, accounted cost and synthetic engine labels. Keep family/supplier/time generalization separate. For investment decisions, establish incremental cash flows and qualified policy review rather than reusing unit cost as the financial answer. For customer-value learning, distinguish preference elicitation from causal identification.

## Updating the method

When a useful source or observed failure appears, record its origin, date, actual inspected scope and the behavior it would change. Add a concrete test, review the attribution and only then promote the change into a versioned release. Do not auto-fetch and execute external instructions. Preserve previous assumptions and source differences. Newer material is not automatically more correct.
