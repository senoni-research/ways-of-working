# What to build next

The first release implements a narrow calculation-and-review foundation. It should be improved through actual failures and permissioned customer cases, not by loading the entire research collection into each prompt.

## Next private prototype slice

Use the supplied source-reading recipe and data contract to connect a reviewed PDF/drawing extraction flow to the existing structured inputs. Obtain explicit permission for each real drawing and quote, an approved inference/storage route, and an independent engineering reviewer. Keep manual correction. Record critical-field extraction, source-location accuracy, unknown detection and correction burden. Do not add production upload capability to a static public demonstration.

A private application can start from the original reference arithmetic. Add identity, authorization, retention and versioned case records before real shared use. A separate private repository is a proposal, not an existing asset or authorization to create one. Do not automatically place product code or customer evidence in the public WoW repository.

A natural next executable contract is the structured cost-breakdown request (T06): a typed schema with mapping statuses (mapped, interpreted, unmapped, unknown, included), line classification by nature, and the same charge-status rules as the quote comparison. A second is the line-by-line price-change decomposition (T07) with exposed shares and dated index bases. Both should begin, as the first slice did, with one synthetic case and an independent hand calculation.

## After the workflow edition

0.3.0 ships the method and a mock replay, not an integration; 0.3.1 makes the mock enforce a listed subset of the method's gates and bindings on synthetic, single-line, per-piece input (see the changelog). The next step is reliability and evidence, not breadth: demonstrate the loop—incomplete request → clarification → reviewable recommendation → authorized correction → visible change → fresh decision → acknowledged handoff—to a buyer before adding any module. The next useful step is a shadow-mode replay with one organization: export a bounded set of already-decided requisitions and their event snapshots under a data agreement, map their real field names to T08/T09, run the harness beside the existing process without returning anything, and compare its routes, exclusions, withheld comparisons and packets with what the buyers actually decided. Record agreement, disagreement with reasons, unsupported cases and effort by role. Only after that does a read-only connector, then a return-decision adapter with the destination's own idempotency support, become worth building. Each of those is a separate authorization.

## Broader methods still deferred

Analogy and parametric estimation (0.2.0 adds selection and validity-domain guidance only; no calibrated tool ships); process-specific ML costing; multi-stage yield/rework and recycling; CAD-derived geometry; richer machine/tool selection; location parameter sets; lifecycle finance and make/buy; formal function/value analysis; general supplier-allocation optimization (0.3.0 adds only a hand-checkable feasibility illustration); price-index computation; bounded automated negotiation; and realized-outcome measurement all need their own inspected derivations, data and tests.

For a predictor, distinguish quotes, actual resource use, accounted cost and synthetic engine labels. Keep family/supplier/time generalization separate. For investment decisions, establish incremental cash flows and qualified policy review rather than reusing unit cost as the financial answer. For customer-value learning, distinguish preference elicitation from causal identification.

## Updating the method

When a useful source or observed failure appears, record its origin, date, actual inspected scope and the behavior it would change. Add a concrete test, review the attribution and only then promote the change into a versioned release. Do not auto-fetch and execute external instructions. Preserve previous assumptions and source differences. Newer material is not automatically more correct.

No continued monitoring, publication or background activity is scheduled by this file.
