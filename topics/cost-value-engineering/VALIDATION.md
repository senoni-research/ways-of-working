# Validation and execution boundary

This file describes the check design. The delivered `EXECUTION_REPORT.txt` contains the actual commands, environment and observed counts for this build. Do not copy counts from an earlier release.

Package checks render expected outputs from canonical inputs, compare generated bytes, enforce source/module/recipe/case/scenario inventories, inspect local links and exact installed file sets, and verify the complete release manifest. The validator is read-only. Negative tests have a passing positive control, make an effective mutation and require the intended diagnostic. Consistently stale mirrors or refreshed hashes cannot substitute for canonical content.

Numerical checks exercise our own declared synthetic contracts: charge statuses, full comparison context, dates, quantity bands, crossover, units, yields, setup/batch counts, labor inclusions, capacity, and a fixed local Decimal arithmetic policy (results independent of the caller's active precision). The reference does not implement markup calculations. They do not execute any downloaded costing workbook or train an ML model. A successful result against hypothetical data is not an industrial benchmark.

Workflow checks replay the synthetic fixture R01 through routing, evaluation, typed correction, decision, mock handoff, duplicate submission, timeout and reconciliation, and assert the authority, freshness and never-enabled-action controls. Since 0.3.1 they also assert that non-event routes stop the case file, that only an explicit “met” is eligible, that every correction type is checked against its owner and either applied or refused, that an approval binds to the full input content, and that the mock destination refuses one key with two payloads. The destination is an in-memory mock; the fixture is marked synthetic and the harness refuses records that are not. Passing these tests shows that the published rules are implementable and self-consistent. It does not show that any procurement system behaves this way, that a connector would be correct, or that a customer would gain value.

No live Cursor, Cline or OpenCode session is executed by these scripts. B01–B45 are behavior specifications. No customer documents, expert factory measurements, supplier-book access, savings outcomes or pilot payments have been evaluated. Document schemas and schematic assets do not establish OCR or CAD functionality. The static website handoff has its own separately documented browser checks.

A private publication-exclusion list may be passed to `tools/scan_publication.py`. No private identifiers are embedded in this tool or its tests. A passed identifier scan is a bounded check, not a substitute for reviewing source expression, image content, permissions or staging.

Source inspection records state text/abstract/documentation limits. No original source articles, captions, slides, datasets or checkpoints are redistributed. Archive preparation makes no GitHub, DNS, hosting or external-message change.
