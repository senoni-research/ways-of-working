# Quickstart

## Cursor

Merge `.vandeput/` and `.cursor/rules/10-vandeput-method.mdc` from `cursor-project/` into the target project. Preserve other rules. Confirm the rule is active in the installed host. Read `cursor.md` manually or explicitly attach it for a one-session alternative; its filename alone does not register a rule.

## Portable: Cline and OpenCode

Merge `.vandeput/` and the supplied `AGENTS.md` content from `portable-project/`. Do not overwrite an existing AGENTS file. For a Cline setup using `.clinerules`, the optional `10-vandeput-method.md` is an alternative to duplicating the same AGENTS loader. For OpenCode, merge the optional `instructions` entry into existing configuration rather than replacing `opencode.json`.

## First useful prompt

> Read the installed Vandeput operating contract and thirteen SupChains practices. I am building `<project and supply decision>`. Inspect the repository and supplied data. Establish the observed target, desired demand target, granularity, issue time, future-known information, risk horizon, baseline and evaluation contract. Build the smallest authorized end-to-end slice, then test one source-grounded improvement. Keep forecasting metrics separate from ordering cost and service. Preserve existing project rules; report what you actually ran and what remains uncertain.

## Verify loading in a fresh session

> Do not modify files. Identify the Vandeput instructions you actually loaded, with paths. Explain how you would handle a stockout zero, overlapping forecast origins, and a week-1 order arriving in week 3. State the difference between installing this handbook and training a forecasting model. Identify the relevant source IDs and one executable arithmetic check.

Run relevant B01–B48 cases in [the examples module](portable-project/.vandeput/80-worked-examples-and-checks.md) and record observed behavior. Static package tests do not guarantee instruction-following.

## With an existing Carey pack

Keep `.carey/` unchanged. Add `.vandeput/`, merge entry instructions and route by the current task. Neither method overrides approved project requirements, information controls or deployment permissions. Do not load both full handbooks into every session; retrieve relevant guidance and surface real disagreements.

## Where project memory goes

Use an approved existing index/handoff store or establish a bounded destination/write policy. The method directory contains reusable public-safe guidance, not client data. Do not append project logs to `memory.md`, upload sensitive originals, or assume that an editor's private chat history is the team evidence ledger.
